# File Integrity Monitor (FIM)

A lightweight, terminal-based File Integrity Monitor written in Python.
It fingerprints a directory with SHA-256 hashes, then lets you audit it
on demand or watch it continuously, flagging any file that's been
modified, created, or deleted — with optional Discord/Telegram alerts.

Built to be scriptable: run `check` from cron for periodic audits, or
run `monitor` as a background daemon for real-time detection.

## Features

- **SHA-256 baselining** — recursively hashes every file in a target
  directory and stores the snapshot in a JSON baseline file.
- **One-time audits** (`check`) — compare the current state against
  the baseline and print a color-coded diff.
- **Real-time monitoring** (`monitor`) — uses OS-level filesystem
  events (via `watchdog`) instead of polling, so changes are caught
  instantly with minimal CPU overhead.
- **Webhook alerts** — optionally push tamper notifications to a
  Discord or Telegram webhook the moment they're detected.
- **Noise filtering** — editor swap files, `.git`, `__pycache__`,
  `.DS_Store`, and similar are ignored by default, and the baseline
  file never flags itself even if it lives inside the watched folder.
- **Graceful error handling** — locked/unreadable files are skipped
  and reported rather than crashing the scan; a missing baseline
  produces a clear message telling you to run `init` first.

## File structure

```
file_integrity_monitor/
├── fim.py             # CLI layer: argparse commands, rich output
├── fim_core.py         # Engine: hashing, baseline, diff, webhooks,
│                        #  watchdog event handler
├── requirements.txt    # Dependencies
└── baseline.json        # Generated by `init` — your saved baseline
```

The logic is split across two files (rather than one) simply because
the full implementation runs well past a single readable file's worth
of code — `fim.py` stays a thin CLI wrapper, `fim_core.py` holds all
the actual engine logic and has no CLI dependencies of its own.

## Installation

Requires Python 3.10+.

```bash
pip install -r requirements.txt
```

This installs:

| Package    | Purpose                                   |
|------------|--------------------------------------------|
| `rich`     | Colored terminal tables and panels          |
| `watchdog` | OS-level filesystem event monitoring        |
| `requests` | HTTP POST for Discord/Telegram webhooks     |

## Usage

### 1. Create a baseline

```bash
python fim.py init /path/to/target_dir
```

Recursively hashes every file under `target_dir` and writes the
result to `baseline.json` in the current directory. Use `--baseline`
to save it somewhere else:

```bash
python fim.py init /path/to/target_dir --baseline /secure/location/baseline.json
```

### 2. Run a one-time audit

```bash
python fim.py check /path/to/target_dir
```

Rescans the directory, compares it against the saved baseline, and
prints a table of any `MODIFIED`, `DELETED`, or `CREATED` files.

Exit codes (handy for cron/CI):

| Code | Meaning                          |
|------|-----------------------------------|
| `0`  | Clean — no changes detected        |
| `1`  | Error (bad path, missing baseline, invalid webhook config) |
| `2`  | Integrity violation(s) found       |

Example cron entry, running an audit every 15 minutes:

```
*/15 * * * * cd /opt/fim && python fim.py check /var/www/html --baseline baseline.json --webhook "$DISCORD_WEBHOOK"
```

### 3. Run continuous monitoring

```bash
python fim.py monitor /path/to/target_dir
```

Starts a `watchdog` observer that reacts to filesystem events as they
happen. Each change is logged with a timestamp and color (green for
new files, red for modified/deleted). Press `Ctrl+C` to stop.

### 4. Webhook alerts (optional)

Add `--webhook <url>` to `check` or `monitor`:

**Discord** — pass the webhook URL directly; alerts are sent as a
formatted embed:

```bash
python fim.py monitor /path/to/target_dir \
  --webhook https://discord.com/api/webhooks/XXXX/YYYY
```

**Telegram** — pass a bot API URL *and* `--telegram-chat-id`:

```bash
python fim.py monitor /path/to/target_dir \
  --webhook https://api.telegram.org/bot<TOKEN>/sendMessage \
  --telegram-chat-id 123456789
```

Any other URL falls back to a generic `{"content": "..."}` JSON POST.

## Ignored by default

The following never get tracked or flagged:

```
*.swp *.swx *.swpx *~ *.tmp *.bak
.DS_Store  Thumbs.db
__pycache__/*  *.pyc
.git/*
```

## How monitoring handles renames

A file rename fires as a `deleted` event for the old path followed by
a `created` event for the new one — there's no ambiguous "renamed"
state to reason about, and both the log output and any webhook alert
reflect that.

## Notes

- `monitor` keeps its comparison baseline in memory only; it does not
  rewrite `baseline.json` as changes come in. Run `init` again when
  you want to accept the current state as the new trusted baseline.
- This tool detects *content* tampering via hash mismatches — it does
  not track permission or ownership changes on their own.
